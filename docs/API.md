# API 구성

서버가 제공하는 주소 목록과 주고받는 값. PRD §9를 구현한 것이며, 실제 코드는 `back/api/`에 있고 `app/api/`는 주소만 가리키는 껍데기다.

## 전체 구조

```
브라우저 ──▶ app/api/.../route.ts   주소만 정의 (2~4줄)
                    │
                    ▼
             back/api/*.ts          요청 검사 · 응답 만들기
                    │
                    ▼
             back/db/*.ts           DB 읽기 · 쓰기
                    │
                    ▼
             Supabase (Postgres)    RLS로 브라우저 직접 접근 차단
```

브라우저는 DB에 직접 연결하지 않는다. Supabase 키는 서버에만 있고, DB의 모든 테이블은 브라우저 역할(`anon`)을 거부한다 (PRD §12). 배정도 서버에서만 만든다 — 클라이언트 랜덤은 금지다 (PRD §3-4).

## 세 가지 원칙

**링크가 곧 열쇠다.** 로그인도, 비밀번호도, 권한 검사도 없다. `slug`를 아는 사람은 누구나 그 조를 읽고 고칠 수 있다 (PRD §3-1). 그래서 `slug`는 추측할 수 없어야 하고, 단어 64개 × hex 6자리 = 약 10억 조합에 `/api/resolve`의 요청 제한을 더해 막는다 (PRD §14).

**하루 배정은 한 줄이다.** `unique (team_id, date)`를 DB가 보장한다. 다시 뽑으면 덮어쓴다. 중간 결과는 저장되지 않는다 (PRD §3-5).

**뽑기는 멱등하다.** 조원 다섯 명이 동시에 `역할 뽑기`를 눌러도 모두 같은 결과를 받는다 (PRD §16).

## POST `/api/teams`

새 조를 만들고 링크를 발급한다. 조 이름은 받지 않는다 (PRD §3-2).

**요청**

```json
{ "names": ["김민지", "박준혁", "이서연", "최태윤", "정하늘"] }
```

이름은 서버에서 다시 정리한다 — 앞뒤 공백 제거, 12자 제한, 빈 이름 제외 (PRD §14). 동명이인은 **막지 않는다.** 화면이 미리 안내할 뿐이다 (PRD §6 S2).

**응답 `201`**

```json
{
  "slug": "mango-7b2c9f",
  "code": "MANGO-7B2C9F",
  "url": "https://groo.app/t/mango-7b2c9f"
}
```

`code`는 `slug`를 대문자로 쓴 같은 값이다. 화상 통화로 불러주기 위한 표기다.

**오류**

| 코드 | 상태 | 언제 |
|---|---|---|
| `NO_MEMBERS` | 400 | 이름이 하나도 없다 |
| `TOO_MANY_MEMBERS` | 400 | 12명을 넘겼다 (PRD §11) |

조를 만들 때 역할 3개(이끄미 · 시간지키미 · 그루)와 조원이 함께 들어간다. 하나라도 실패하면 조를 지운다. 역할이 없는 조가 남으면 `역할 뽑기`가 영원히 안 되는데 사용자는 이유를 알 수 없다.

## GET `/api/teams/[slug]`

조 하나를 통째로 읽는다. 화면이 이 응답만으로 S3(조원 확인)이나 S5(결과)를 그릴 수 있게 만들었다. 이니셜 같은 계산도 서버가 채워 보낸다.

**응답 `200`**

```json
{
  "slug": "mango-7b2c9f",
  "code": "MANGO-7B2C9F",
  "createdAt": "2026-03-12T00:31:00.000Z",
  "createdToday": true,
  "members": [
    { "id": "…", "name": "김민지", "initial": "민", "orderIndex": 0, "active": true }
  ],
  "roles": [
    { "id": "…", "key": "lead", "name": "이끄미", "emoji": "🎯",
      "description": "범위와 쉬는시간…", "priority": 0, "isDefault": false }
  ],
  "today": null
}
```

`createdToday`가 `true`인 날에만 링크 배너를 띄운다 (PRD §6 S3).

`today`에 값이 있으면 화면은 조원 확인을 건너뛰고 결과로 바로 간다 (PRD §6 S3). 모양은 아래 배정 응답과 같다.

`members`에는 조에 남아 있는 사람만 들어간다. 명단에서 내린 사람은 DB에 `active = false`로 남아 지난 기록의 이름을 채운다.

**오류**: `TEAM_NOT_FOUND` 404

## PUT `/api/teams/[slug]/members`

명단을 한 번에 저장한다. 추가 · 이름 수정 · 순서 변경 · 내리기가 이 하나로 처리된다.

**요청**

```json
{
  "members": [
    { "id": "기존-조원-id", "name": "김민지" },
    { "name": "새로 온 그루" }
  ]
}
```

- `id`가 있으면 기존 조원 → 이름과 순서를 맞춘다
- `id`가 없으면 새 조원 → 추가한다
- **목록에서 빠진 기존 조원 → 지우지 않고 `active = false`로 내린다**

마지막 항목이 중요하다. 즉시 지우면 되돌릴 수 없고 지난 기록의 이름도 사라진다 (PRD §14). 화면의 `되돌리기`는 이 값을 다시 `true`로 만든다.

배열 순서가 그대로 명단 순서가 된다.

**응답 `200`**: `GET /api/teams/[slug]`와 같은 형태

**오류**

| 코드 | 상태 | 언제 |
|---|---|---|
| `NO_MEMBERS` | 400 | 이름이 남아 있는 조원이 0명 |
| `TOO_MANY_MEMBERS` | 400 | 12명 초과 |
| `BAD_REQUEST` | 400 | 이 조에 없는 조원 `id`를 보냈다 (명단이 그사이 바뀐 경우) |
| `TEAM_NOT_FOUND` | 404 | |

## POST `/api/teams/[slug]/assign`

역할을 뽑는다. **화면이 이걸 먼저 부르고, 응답을 받은 뒤에 카드 뒤집기 연출을 시작한다.** 연출은 결과를 만들지 않는다 (PRD §6 S4).

**요청** — 참여자 목록만 보낸다. 빈자리는 여기 넣지 않는다.

```json
{ "presentMemberIds": ["id1", "id2", "id3", "id4"] }
```

**응답 `200`**

```json
{
  "date": "2026-03-12",
  "assigned": [
    {
      "role": { "key": "lead", "name": "이끄미", "emoji": "🎯", "description": "…" },
      "member": { "id": "…", "name": "최태윤", "initial": "태" }
    },
    {
      "role": { "key": "keeper", "name": "시간지키미", "emoji": "⏱️", "description": "…" },
      "member": { "id": "…", "name": "김민지", "initial": "민" }
    }
  ],
  "groos":  [{ "id": "…", "name": "박준혁", "initial": "준" }],
  "absent": [{ "id": "…", "name": "이서연", "initial": "서" }],
  "unfilledRoles": [],
  "updatedAt": "2026-03-12T00:41:00.000Z"
}
```

`assigned`는 `priority` 순이다. `groos`와 `absent`는 명단 순서다.

`unfilledRoles`는 사람이 부족해 비운 역할이다. 참여자가 1명이면 이끄미만 배정되고 시간지키미가 여기 들어온다 (PRD §7).

### 멱등성

**같은 날 배정이 이미 있으면 새로 뽑지 않고 그것을 그대로 돌려준다.** 조원 다섯 명이 동시에 눌러도 결과가 하나다. 구현은 두 단계다.

1. `assignments`에 `(team_id, date)`로 한 줄을 넣는다. 이미 있으면 아무것도 하지 않는다 — DB의 `unique`가 경쟁을 정리한다
2. 그 줄에 내용이 비어 있을 때만 뽑아서 채운다

2단계 덕분에 **줄만 만들고 죽은 요청도 다음 요청이 복구한다.** 빈 결과 화면이 남지 않는다.

`presentMemberIds`가 달라도 이미 배정이 있으면 무시된다. 참여자를 바꾸고 싶으면 `reroll`을 쓴다.

**오류**

| 코드 | 상태 | 언제 |
|---|---|---|
| `NO_PARTICIPANTS` | 400 | 참여자가 0명이다. "명단에서 참여로 바꾼 뒤 다시 뽑아주세요" |
| `NO_ROLES` | 500 | 조에 역할이 없다 (정상적으로는 생기지 않는다) |
| `TEAM_NOT_FOUND` | 404 | |

없는 조원 `id`를 보내면 조용히 걸러낸다. 명단 저장과 배정이 겹칠 때 실제로 발생한다 (PRD §14).

## POST `/api/teams/[slug]/reroll`

다시 뽑는다. 요청과 응답 모양은 `assign`과 같지만 **기존 배정을 덮어쓴다.**

### PRD에 없어서 정한 것

**직전 당첨자를 그 역할 후보에서 뺀다.**

PRD §7은 "같은 알고리즘을 다시 돌려 덮어쓴다"고만 적어놨다. 그대로 하면 방금 뽑힌 사람이 후보에 그대로 남는다. 시뮬레이션해 보니 **5명 조에서 49%가 같은 사람이 다시 나왔다** (후보가 평균 2.3명뿐이라서). 버튼이 아무 일도 안 한 것처럼 보이므로 그 역할에 한해 직전 당첨자를 뺀다.

- **역할이 바뀌는 것은 막지 않는다.** 직전 시간지키미가 이번에 이끄미가 되는 것은 다시 뽑힌 것이다
- **1~2명 조에서는 되돌린다.** 빼면 후보가 0명이 되므로

다시 뽑기 횟수는 어디에도 저장하지 않고 화면에도 표시하지 않는다 (PRD §6 S5).

오늘 배정이 아직 없으면 첫 뽑기와 똑같이 동작한다.

## GET `/api/resolve?code=MANGO-7B2C9F`

코드를 링크 주소로 바꾼다. 기기가 바뀌거나 시크릿 모드라 브라우저에 최근 목록이 없을 때 쓰는 유일한 통로다 (PRD §14).

**응답 `200`**

```json
{ "slug": "mango-7b2c9f" }
```

입력을 너그럽게 받는다. 다음이 모두 같은 코드로 인식된다.

```
MANGO-7B2C9F    mango-7b2c9f    MANGO7B2C9F
MANGO 7B2C9F    MANGO--7B2C-9F    (앞뒤 공백 포함)
```

**오류**

| 코드 | 상태 | 언제 |
|---|---|---|
| `TEAM_NOT_FOUND` | 404 | 형식이 틀렸거나 그런 조가 없다 |
| `RATE_LIMITED` | 429 | 1분에 20번을 넘겼다 |

형식 오류와 없는 조를 **같은 응답으로** 답한다. 구분해서 알려주면 "형식은 맞는 코드"라는 정보를 주게 되어 무작위 대입에 도움이 된다.

요청 제한은 서버 메모리에 기록한다. 서버 인스턴스가 여러 개면 각자 센다. 사람이 손으로 넣는 속도로는 걸리지 않는다.

## 오류 응답의 공통 모양

```json
{ "error": { "code": "NO_PARTICIPANTS", "message": "참여하는 그루가 없어요. 명단에서 참여로 바꾼 뒤 다시 뽑아주세요." } }
```

`message`는 그대로 화면에 띄울 수 있게 썼다. 문구 규칙 (PRD §17):

- **사과하지 않는다.** 무엇이 잘못됐고 어떻게 하면 되는지 적는다
- 사용자를 **그루**, 불참을 **빈자리**라고 쓴다

예상하지 못한 오류는 내부 사정을 감춘 채 `SERVER_ERROR` 500으로 나간다. DB 오류 메시지가 브라우저로 새면 안 된다.

| 코드 | 상태 |
|---|---|
| `BAD_REQUEST` | 400 |
| `NO_PARTICIPANTS` `NO_MEMBERS` `TOO_MANY_MEMBERS` | 400 |
| `TEAM_NOT_FOUND` `NO_ASSIGNMENT` | 404 |
| `RATE_LIMITED` | 429 |
| `NOT_CONFIGURED` | 503 (`.env.local`이 비어 있다 — 개발 중에만) |
| `NO_ROLES` `SERVER_ERROR` | 500 |

## 날짜

모든 `date`는 **한국 시간(KST) 기준 `YYYY-MM-DD`**다. 서버는 UTC로 돌기 때문에 `shared/date.ts`의 함수만 써서 계산한다. 그러지 않으면 오전 9시 이전에 하루가 어긋난다 (PRD §14).

## 타이머 (M2)

세 주소 모두 **같은 모양**을 돌려준다. 화면은 응답을 그대로 상태로 삼으면 되고, 무엇이 바뀌었는지 따로 계산하지 않는다.

```json
{
  "plan": { "studySec": 2400, "breakSec": 600 },
  "current": {
    "id": "…", "kind": "study", "plannedSec": 2400,
    "startedAt": "2026-09-04T01:00:00.000Z",
    "pausedAt": null, "pausedTotalSec": 0, "endedAt": null
  },
  "sessions": [ "…" ],
  "totalStudySec": 3780,
  "studyCount": 2,
  "serverNow": "2026-09-04T01:16:46.000Z"
}
```

### 남은 시간을 서버가 세지 않는다

서버는 `startedAt`(서버 시각)과 `plannedSec`만 확정한다. 남은 시간은 화면이 그 값으로 계산한다 (PRD §10). 그래서

- 탭을 닫았다 열어도 이어진다 — 계산에 쓰는 것이 시작 시각뿐이다
- 백그라운드 탭에서 `setInterval`이 느려져도 어긋나지 않는다 (PRD §14)
- 여러 명이 봐도 같은 숫자가 보인다

`serverNow`는 **시계 오차 보정용**이다. 화면은 (서버 시각 − 내 시각)만큼 밀어서 쓴다. 사용자 컴퓨터 시계가 3분 틀어져 있어도 남은 시간이 맞다.

### GET `/api/teams/[slug]/timer/sessions`

PRD §9 목록에는 없지만 필요하다. 탭을 닫았다 열면 현재 세션을 다시 받아야 한다.

**읽으면서 뒤처진 세션을 정리한다.**

- 예정 시각이 지났는데 아무도 안 넘긴 세션 → 예정 시각에 끝난 것으로 처리
- 시작한 지 24시간이 지난 세션 → 끝난 것으로 처리 (일시정지한 채로 하루를 넘긴 경우, PRD §14)

**다음 단계를 자동으로 시작하지는 않는다.** 몇 시간 방치했는데 그 사이 세션이 여러 번 돌아간 것처럼 꾸미면 기록이 거짓이 된다. 화면을 보고 있던 클라이언트가 자동으로 넘기고, 아무도 없었으면 다음에 연 사람이 시작한다.

### POST `/api/teams/[slug]/timer/sessions`

```json
{ "kind": "study", "plan": { "studySec": 2400, "breakSec": 600 } }
```

`plan`은 **처음 시작할 때만** 보낸다. 그 값이 그날의 약속으로 배정에 저장되고, 다른 조원 화면도 같은 길이로 돌아간다. 이후 단계 전환에서는 `kind`만 보낸다.

**이미 진행 중인 세션이 있으면 새로 만들지 않고 그것을 돌려준다.** 시간이 다 되는 순간 여러 화면이 동시에 다음 단계를 알리기 때문이다. DB에 "끝나지 않은 세션은 한 배정에 하나"를 보장하는 부분 unique 인덱스를 둬서 경쟁을 DB가 정리한다.

| 코드 | 상태 | 언제 |
|---|---|---|
| `NO_ASSIGNMENT` | 404 | 오늘 역할을 아직 안 뽑았다 |
| `BAD_REQUEST` | 400 | 약속이 없거나, 쉬는 시간이 0분인데 쉬려고 한다 |

### PATCH `/api/teams/[slug]/timer/sessions/[id]`

```json
{ "action": "pause" }
```

`action`은 `pause` · `resume` · `end` 중 하나다.

**같은 동작을 두 번 보내도 결과가 같다.** 조원 둘이 동시에 일시정지를 눌러도 멈춘 시간이 두 배로 쌓이지 않는다. 이미 끝난 세션에 보내면 아무것도 하지 않고 지금 상태를 돌려준다.

일시정지는 `paused_at` + `paused_total_sec`으로 정확히 계산한다. 멈춘 만큼 종료 예정 시각이 뒤로 밀린다 (PRD §10).

### 누적 학습시간

**세션이 속한 배정 기준으로 센다. 날짜를 보지 않는다** (PRD §14). 23:50에 뽑고 00:10에 타이머를 켜면 날짜가 바뀌는데, "오늘"로 집계하면 끊긴다.

한 세션이 채운 시간은 **계획한 길이를 넘지 않는다.** 아무도 안 보는 사이 두 시간이 지났어도 40분 세션은 40분만 채운 것이다. 그러지 않으면 누적이 부풀려진다.

### DB 추가 (`0002_timer.sql`)

PRD §8 스키마에 없던 것 두 개를 넣었다.

1. `timer_sessions`에 부분 unique 인덱스 — 진행 중인 세션은 한 배정에 하나
2. `assignments.study_sec`, `assignments.break_sec` — 그날의 약속. 세션 기록만 보고 유추하면 쉬는 시간을 0분으로 정한 조를 구분할 수 없다 (쉬는 세션이 아예 안 만들어지므로)
