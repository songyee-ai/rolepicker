# 배포하기 (Vercel)

인터넷에 올려서 조원들이 링크로 들어올 수 있게 만든다. 무료이고 10분쯤 걸린다.

지금은 `localhost`에서만 돌아간다. 그 주소는 **내 컴퓨터에서만** 열리므로 조원에게 보내도 안 열린다.

---

## 1. Vercel 계정 만들기

1. https://vercel.com 에 접속
2. **Continue with GitHub** → 깃허브 계정으로 로그인
3. 무료 요금제(Hobby)를 고른다. 카드 등록을 요구하지 않는다

## 2. 저장소 가져오기

1. 대시보드에서 **Add New...** → **Project**
2. 목록에서 **rolepicker** 를 찾아 **Import**
   - 안 보이면 `Adjust GitHub App Permissions` 를 눌러 이 저장소에 접근을 허용한다.
     저장소가 비공개라 처음에는 목록에 안 나올 수 있다
3. **Framework Preset** 이 `Next.js` 로 잡혔는지 확인한다 (자동으로 잡힌다)
4. Root Directory, Build Command 는 **건드리지 않는다**

## 3. 설정값 두 개 넣기 — 이 단계가 제일 중요하다

**Deploy 를 누르기 전에** `Environment Variables` 칸을 편다.

`.env.local` 에 넣었던 것과 **똑같은 두 값**을 넣는다.

| Name | Value |
|---|---|
| `SUPABASE_URL` | `https://xxxxxxxx.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | `eyJ...` (긴 글자) |

`.env.local` 파일을 열어서 복사하면 된다.

```bash
notepad C:/airrel_work/rolepicker/.env.local
```

> 이 값을 빼먹으면 배포는 되지만 조를 만들 때 `DB를 아직 연결하지 않았어요` 가 뜬다.
>
> `service_role` 키를 Vercel에 넣는 것은 안전하다. Vercel의 서버에만 저장되고
> 브라우저로 나가지 않는다 — 이름에 `NEXT_PUBLIC_` 이 없기 때문이다 (`docs/SECURITY.md`).

## 4. Deploy

**Deploy** 를 누르고 2~3분 기다린다. 끝나면 주소가 나온다.

```
https://rolepicker-xxxx.vercel.app
```

이 주소를 열어서 `새 조 만들기` 가 되면 성공이다.

## 5. 서버 위치를 서울로 (선택, 하지만 권함)

Vercel은 기본으로 미국에서 돌린다. Supabase는 서울에 있으므로, 그대로 두면
화면 한 장 여는 데 태평양을 몇 번 왕복한다. 눈에 띄게 느려진다.

1. 프로젝트 → **Settings** → **Functions**
2. **Function Region** 을 `Seoul, South Korea (icn1)` 로 바꾼다
3. **Deployments** 탭에서 최근 배포의 `⋯` → **Redeploy**

요금제에 따라 이 설정이 안 보일 수 있다. 없으면 그냥 넘어간다 — 느릴 뿐 동작은 한다.

## 배포한 뒤

### 조 링크가 바뀐다

배포한 주소에서 **새로 조를 만들어야** 조원과 공유할 수 있다.
`localhost` 에서 만든 조는 같은 DB에 들어 있지만 주소가 달라서 그대로는 못 쓴다.
코드(`MANGO-7B2C9F`)를 배포 주소의 첫 화면에 입력하면 같은 조로 들어갈 수 있다.

### 고치면 자동으로 다시 배포된다

깃허브에 올리면(`git push`) Vercel이 알아서 다시 배포한다. 따로 할 일이 없다.

### Supabase가 잠들 수 있다

무료 요금제는 **7일 동안 아무도 안 쓰면 프로젝트를 멈춘다.** 매일 쓰면 문제없고,
방학처럼 오래 안 쓰면 Supabase 대시보드에서 `Restore` 를 한 번 눌러야 한다.

## 누가 쓸 수 있나 — 알고 배포하기

**주소를 아는 누구나 접속해서 자기 조를 만들 수 있다.** 로그인이 없기 때문이다 (PRD §3-1).
모르는 사람이 들어와도 **우리 조는 못 본다** — 조는 링크로만 열린다.

무엇이 막혀 있고 무엇이 안 막혀 있는지는 아래와 같다.

### 막혀 있는 것

| | 어떻게 |
|---|---|
| 남의 조 훔쳐보기 | 링크를 모르면 못 연다. 조합 약 10억 개 |
| 코드 찍어맞히기 | `/api/resolve` 는 한 곳에서 1분에 20번까지 |
| 조를 스팸으로 만들기 | 한 곳에서 한 시간에 20개까지 |
| 검색엔진에 뜨기 | `robots.txt` + 조 화면 `noindex` |
| DB에 직접 접근 | 모든 표에 RLS. 브라우저 역할은 거부 (`docs/SECURITY.md`) |
| 남의 이름으로 스크립트 심기 | React가 글자를 그대로만 그린다. HTML 삽입 지점이 없다 |

### 막혀 있지 않은 것 (설계상)

- **링크를 아는 사람은 누구나 고칠 수 있다.** 조원이든 아니든. 링크가 곧 열쇠다 (PRD §3-1).
  링크가 새면 새 조를 만들어야 한다 — 그게 이 서비스의 "비밀번호 바꾸기"다
- **모르는 사람이 자기 조를 만드는 것**은 막지 않는다. 우리 조와는 아무 상관이 없다

### 링크가 새면

조를 새로 만들고 새 링크를 공유한다. 지난 기록은 옛 링크에 남고 새 조는 0부터 시작한다
(PRD §6 S1의 "조가 새로 편성되면 새 링크").

### 더 잠그고 싶으면

수업용으로만 쓰고 모르는 사람이 조를 만드는 것조차 막고 싶다면, `새 조 만들기` 에
우리 반만 아는 한 마디를 넣게 할 수 있다. 로그인은 아니고 문 앞의 암구호에 가깝다.
PRD §5가 "로그인·회원가입·이메일·PIN 없음"으로 정해둔 것과는 부딪히므로, 필요해지면 그때 정한다.

---

## 안 될 때

| 증상 | 확인할 것 |
|---|---|
| `DB를 아직 연결하지 않았어요` | 3번의 설정값 두 개. 넣은 뒤 **Redeploy** 해야 반영된다 |
| 빌드가 실패한다 | Vercel의 `Building` 로그 맨 아래 빨간 줄을 그대로 알려주세요 |
| 목록에 저장소가 안 보인다 | 비공개 저장소라서 그렇다. `Adjust GitHub App Permissions` 로 허용 |
| 느리다 | 5번의 서버 위치를 서울로 |
